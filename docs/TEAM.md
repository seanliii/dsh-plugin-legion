# 一次组队，让 DSH 自己持续往前走

本页说明 **已公开的 0.5.0** 自动流程，安装入口见[固定 Git／Discover](MARKET.md#v050)。
旧的 `v0.4.2` 固定标签保持不变；原生安装、公开发行及模型效果分别核验。
发行归档内“开发版”文案保留封包时点，当前发行状态以 Release 和本页后验说明为准。

## 你只需要完成一次组队

```text
选战友           定协作              组建并自动开工
DSH 是主场  →  自主组织（默认）  →  第一轮自动投递
其他成员加入     或指定带队者         以后默认每周继续
               或写你的要求         随时暂停、修改、再做一轮
```

1. 在 DSH 侧栏打开 **军团 → 我的军团**，选择一个工作会话。
2. 选择可执行成员，或者留空让军团自己选人。DSH 的模型、工具与工作区仍是你的
   主场。添加新成员继续使用现有的 **添加能力** 和合法接入流程；勾选不是安装。
3. 默认采用 **自主组织**。需要指定带队者时，从已选成员中选择；自定义协作要求是
   给战队的上下文，不替所有任务规定同一套步骤。
4. 写下希望持续改善的目标。**自主改进默认开启，后续默认每周一次**，可改每日或
   只做首次。点击 **组建战队并自动开工**后保存配置并自动安排，无第二道开启确认。

后续的工作由 DSH 当前会话里的模型推动，而不是连接器偷偷启动另一个模型。
模型根据真实需求、当前工具、可用成员、源码和失败记录决定如何研究、协作、
改善工具／Skill／适配并验证变化。每轮具体做什么由模型判断，不是固定质量评分器。

## 看得清是不是真的在工作

- **自动工作已安排**：DSH 的原生任务目录中确实存在本流程的活动任务。
- **已投递**：原生调度保存了发往该会话的消息回执。它不是模型完成或改进有效。
- **打开工作会话，看实际结果**：直接进入同一个 DSH 会话，查看模型的工具调用、
  实际修改、失败、产物与复验。
- **模型不可用**：页面读取原生模型目录及该会话的模型选择，显示缺少可用模型或
  最近的原生执行错误。不能靠一个“已开启”标签掩盖这项缺口。
- **部分安排／结果未确认**：保留成功项和原操作键；核对目录后重试，不换编号重发。
- **只有首次、没有周期**：分别显示，不因为刷新一次就把缺失的周期任务说成成功。
  缺少记录可能来自未安排、失败或主动暂停，原因不明就不猜。
- **任务仍使用旧设置**：对照原生计划保存的内容与当前默认配置，明确提醒尚未同步；
  不是把界面上的新开关当成旧任务已经被改好。

没有模型时可以先保存和安排，但不会凭空执行。请在 DSH 原生会话配置自己的模型
或 API Key；配置好后点 **现在再做一轮**，或等待后续周期任务。模型调用使用原生
账号及用量，不由此插件免费提供，也不证明远程模型权重已被训练或升级。

## 暂停和恢复

- **暂停后续自动工作**只处理这个会话内、本流程标记的未来任务，不影响其他计划。
  已开始／已投递的工作不被撤回，需要停止当前模型时在原会话操作。
- **恢复／核对自动安排**先查原生目录。重复点启动、刷新、重载或重启，不会因为
  页面丢了内存就再建同一条首次任务。
- **现在再做一轮**是明确的新一轮。回执丢失时保留同一个操作键，按钮变为重试。
- 如果配置已保存但页面在自动开工前关闭，重新打开同一地址和会话，会先新鲜读回
  原生配置，再恢复这次已发起的操作。任务创建后丢回执也复用原操作键，不另开一单。
  浏览器只保存少量待完成操作的身份和配置摘要，不保存指令原文或凭据；任务仍由
  DSH 原生目录管理。主动暂停、正常完成、明确拒绝都不会在刷新后被擅自重开。
  清空浏览器数据、换浏览器或删除原生记录会失去相应恢复线索，不能许诺跨设备永久去重。
- 正常暂停会删除未来的原生任务；DSH 的删除同时清理该任务自己的调度历史。
  已投递会话内容保留，但被用户刻意删除的任务不能再用来永久去重。
- 已逾期却尚未成功投递的活动任务也可以暂停；“时间到了”不等于“模型已经执行”。
- DSH Host 必须运行。关闭进程、机器关机或睡眠时不会有另一个后台服务代跑；
  重新启动后由 DSH 恢复其原生计划，不保证离线期间准时执行。

## 配置与权限不会被偷偷改变

`teamProfile` 和原 `candidateHarnesses` 通过 DSH 原生配置保存，作用域是当前
**profile**，不是单个会话。自动任务绑定创建时的会话。更换工作会话不会转移旧任务；
在一个会话里更新计划，也不会静默改写其他会话的历史安排。
因此界面会区分**新任务默认配置**和**这个会话的实际计划**：要更新一个旧会话，
回到该会话核对并同步；要停它的后续工作，直接暂停。不能把在 B 会话里关闭默认进化，
描述成 A 会话的旧任务已经被撤回。

未配置战队的旧用户行为不变。仅打开页面、导入或启用插件，不会自动消费模型。
只有用户完成组队并提交，才创建首次和周期任务。

开启自主改进不等于取消原授权。安装新仓库、执行构建脚本、外发资料、发布代码、
采购或扩大访问范围仍走原权限。关闭自主改进后只做能力发现与当前目标，不进行
自我修改。关闭该设置不会追回已经投递的旧指令。

## 开发者接线

- `lib/team.js`：校验用户战队配置，生成明确标为用户配置的上下文。
- `lib/client.js`：沿原 `submit` 追加这份上下文，保留原 query、工程、候选、身份、
  去重与恢复。配置改变后不能拿同一个任务 key 误领旧结果。
- `lib/team-flow.js`：复用当前 DSH 的 `schedule.create/catalog/update/delete`。
  首次与手动再跑使用 `after_seconds`；周期使用 `every_seconds`。没有自建常驻
  定时器、计划任务数据库、模型调用器或新 Agent。
- 原 `/legion-panel` 扩展 `flow_status`、`flow_start`、`flow_pause`、`flow_run`。
  会话身份来自原生 invocation，`flow_run` 只接受稳定操作键，不接受外部身份。
- `client/index.js`：组队、配置、状态与原会话导航。控制器隔离不同会话和迟到回执，
  未确认的原生写入不能显示为完整成功。

原始任务、执行、文件、正式导出与进化效果继续分别展示。建立这个流程不等于
证明所有成员均已安装，或自动普遍胜过任一顶尖 Harness。
