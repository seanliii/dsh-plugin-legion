# 组队后自动协作、发现与进化

## 已批准的目标

用户确认“选战友 → 定协作 → 开进化 → 共同开工”，随后明确：
**“建立流程即可，让他自动开启，让自己的 dsh 变强。”**

因此本次建立真实可运行流程，不另造完整 Agent、质量裁判或第二套调度器：
组队保存后自动安排首次工作和周期工作，使用 DSH 当前会话、模型、工具与原生调度。
首次不再要求另点“同意开启进化”；仍允许关闭进化或暂停后续自动任务。

## 产品界面

军团首页以组队为主，而不是工具管理为主：

1. **选择谁与你并肩作战**：当前 DSH 始终是用户入口与本地执行者；选择可用
   Harness 候选、让团队自动选人，或通过已有“添加能力”／“连接配置”接入。
   注册、安装、配置、实跑分别呈现；非执行角色不能冒充战友。
2. **协作方式**：自主组织（默认）、指定带队者、我的协作要求。后两项是当单上下文，
   不把角色、调用序列或答案写死在平台。已选队长必须属于候选成员。
3. **持续变强**：默认开启自进化、互相改进、协作与工具改进；显示默认每周
   发现一次新 Harness／开源工具。可选每日或仅手动，可关闭进化而继续发现。
4. **组建并自动开工**：保存原生配置，然后通过原生任务安排首次工作与周期任务；
   刷新后可以读取实际任务、下次时间、投递记录和暂停入口。

设置不自动取得模型或安装所有成员。没有可用模型时仍明确区分“任务已安排”
和“模型已执行”，给出原生会话入口，不显示虚假的成长百分比或效果保证。

## 单一事实源与复用

- `teamProfile` 与已有 `candidateHarnesses` 通过 DSH 原生配置原子保存。
- 原 `LegionClient.submit` 保留 `mode: auto` 与已有 candidate_harnesses 协作入口，
  追加已配置的组队要求作为显式用户上下文；不更改核心授权、项目绑定或恢复语义。
- 首次与周期工作由 `ctx.schedule` 持久化并自动投递到当前原生会话。插件不设
  `setInterval`、不新开后台模型、不开新的计划任务数据库。
- 工作指令让 DSH 自己读取可见工具／Skill、现有成员、当前需求与失败证据，
  按需协同、研究来源、改善合法本地工具／Skill／适配，并验证后复用。
  不借用旧 `evolve_config` 的偏好统计冒充完整进化，不在提示里指定领域答案。
- 同一会话的任务通过稳定标记关联；重复“启动”、响应不明及重新加载先查原生
  catalog，不重复发首次任务。明确再跑使用新的操作键。
- 暂停只移除本流程未来投递；不删除会话成果、不声称取消了已经开始的模型工作。
- 发现结果和进化报告写在该原生会话，用户可直接打开；记录／安排／投递不等于效果。

## 精确配置

`teamProfile`（可省略，旧版不改变行为）：

```json
{
  "name": "我的战队",
  "goal": "让我的 DSH 和战队在真实工作中持续变强",
  "collaboration": "auto",
  "leader": "",
  "instructions": "",
  "evolutionEnabled": true,
  "cadence": "weekly"
}
```

`collaboration` 为 `auto | leader | custom`；`cadence` 为 `weekly | daily | manual`。
成员仍只来自已有 `candidateHarnesses`。文本有界、未知配置字段拒绝；
不接受模型参数中的用户身份、凭据或新授权。

## 原生工作入口

工作台扩展四个动作：`flow_status`、`flow_start`、`flow_pause`、`flow_run`。
`flow_run` 需要稳定的 `key`；其余无外部 session／owner 参数。
从 `executionFrom(invocation)` 获取原生会话和取消信号。

首次启动产生一条 `after_seconds` 任务；weekly/daily 产生原生 `every_seconds`
周期任务。原生 `catalog` 是事实源，状态只表示未安排、已安排、已投递、失败
或部分安排。并发、取消、写入后回执丢失须先核对 catalog 再决定，不盲重试。
删除或编辑任务保留原生记录的身份和冲突检查，不修改其他用户任务。

## 本次验收

- 配置、老版本兼容、每次提交的组队上下文、错误脱敏与未知字段拒绝。
- 真实官方调度：首次投递、周期任务、重复启动不重复、暂停、重启后同一任务；
  原生内存测试与真正 Host 的持久化／投递分别留证。
- 真实 DSH 页面：完成向导、自动启动、查看任务、修改设置、刷新保存、
  新发现／进化结果的原会话入口；截图逐张查看。
- 有合法可用模型则做一个真实流程；若没有，准确展示缺失能力与投递状态，
  不用替身模型或安装回执伪造自治成效。
- 代码、包、原生安装物一致；旧发行标签与历史证据保持，不让新代码覆盖旧版本。

## 不在本次范围

不会自动训练模型权重、修改 DSH 安全机制、在用户未知时外发资料、发布代码、
无授权购买服务或安装任意仓库。已有成员接入、正式成果出口及本机隔离继续生效。
这是让原生 DSH 自主工作的流程，不是承诺自动普遍超过任何单家。
