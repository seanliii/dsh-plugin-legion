# Legion：集结顶尖 Harness，共同进化，对标世界级成果

**你给一个目标，战队自主研究、协作和互用工具，以顶级成果为参照反复改进，把同一个作品做完整。**

用户拥有的应是一支共同变强的战队，而不是更大的模型菜单。“开放接入各路优秀 Harness”
不等于“已装好并验证全部 Harness”；“对标世界级成果”也不等于“每次已经世界第一”。
产品要用具体作品和运行事实缩小这段差距，不靠绝对化宣传抹掉差距。

DSH 是进入这支战队的原生工作入口，独立军团核心负责运行、连接、上下文与恢复。找插件、接 GitHub、安排后续工作都是实现这一目标的手段，不是把产品缩成工具目录或调度表。

**当前定位：技术预览。** 0.5.0 的已验运行是单 DSH 作者交付；0.5.1 已发生限定的双 Harness 评审与反馈采用。协作已有实例，但全团工具互用、改进自动传播与普遍行业领先仍未证明。[版本证据与发行状态](PLAN.md#v051)

## 一支战队，不是更多聊天窗口

### 同一目标：一起完成一件事

用户提出想得到的结果。成员保留各自原生的工具、上下文、执行与恢复长处，围绕同一份工作自主组织、分工、检查与补位。后续修改接回原作品，而不是重复开几个互不相关的任务。

“任何顶尖 Harness 都能加入”是开放接入的方向，不是宣称它们已经全部安装和实跑，也不是每个简单问题都机械启动所有成员。怎样协作应由当前任务和可用条件决定。

### 互用工具：一位成员的长处能帮助另一位

有用的能力不应困在各自的窗口里。团队需要能发现合法可用的工具、接口与 Skill，按原生授权调用，并把相关结果送回同一个任务。

已有的工具、消息和续作接口承接这类协作。接口存在、工具可见、实际调用、结果投递、另一位成员实际采用，是不同的事实；不能由一张清单推断所有成员已经互通。

### 世界对标：比较的是成果，不是助手名字

从当下用户目标出发，研究真正可打开、可核对的高水平作品和做法；依据参照理解什么值得做，
再用实际操作与结果发现差距，回到原作品继续修改。研究何时足够、如何分工和如何验证，
由战队根据当单情况决定，不给所有任务强塞同一套质量门。

保留参照来源、读取范围、关键差异与复验结果。“看过某个优秀项目”仅证明研究，
“按它改了一轮”仅证明发生改动；只有同条件的实际比较才能支持某个具体维度上的提升或胜出。
本次 0.5.1 验收是产品状态与协作接线的改进，不是一场行业效果竞赛。

### 改进传播：不止自己改好一次

目标是：成员从真实工作和失败中发现问题，实施改进并在原作品复验，再让其他成员或后续任务真正用上。

```text
共同的用户目标
      ↓
成员按任务组织协作，使用合法工具与能力
      ↓
同一个真实作品得到改进与复验
      ↓
有效改进被其他成员或后续任务实际采用
```

这是目标体验与需要的证据，不是给平台规定固定角色或强制步骤。不另造一个答题器、评分裁判或领域工作流来替成员判断。

| 全团工具互用和改进自动传播 | 现有研究、工具桥、协作与知识入口承接部分机制，本次已有跨 Harness 的评审反馈采用。 | 反馈采用不等于工具全互通；改进在后续任务中自动传播及长期收益仍待验证。 |
| 相对单家的能力提升 | 保留团队带来更强结果的产品目标。 | 没有充分对照时，不宣称普遍超过顶尖单家；调用数、token 用量和绿测不是能力排名。 |

依据见[0.5.0 公开与模型复验](PLAN.md#v050)、[0.5.1 协作与验收记录](PLAN.md#v051)、[核心能力地图](CORE.md#军团的核心没有变成一句宣传语)和[生态原则](ECOSYSTEM.md#co-evolving-team)。它们保留各自的版本与条件，不合并成一个“全部已验证”的结论。

**0.5.0 的历史范围：** 那轮单作者工作没有解决核心候选 Codex 的配置问题，也没有让另一成员采用新工具。51 项测试检验的是辅助工具本身，不是战队能力。更多工具调用、测试或 token 消耗都不能代替共同交付和实际收益；效率需要单独看耗时、用量及缓存分项和同任务对照。

## 分清作者、成员与计划

| 对象 | 它做什么 | 不能混成什么 |
|---|---|---|
| **DSH 作者模型** | 在当前原生会话中理解目标、使用可见工具、产出文件，并按需要组织协作。 | DSH 自己能运行，不等于核心里的每个 Harness 已配置。 |
| **核心成员** | 保留自己的原生执行方式、模型与授权，接收合法委托。 | 被选中、有适配入口或名字出现在目录里，不等于已经实际完成请求。 |
| **原生工作计划** | 到时把明确的工作投递回所属 DSH 会话。 | 已安排、已投递，不等于模型已完成，更不等于能力已经进化。 |
| **默认配置与会话快照** | 默认偏好属于 DSH profile；已有计划保留所属会话和创建／更新时的内容。 | 在一个会话改默认开关，不会自动改写所有旧会话计划。 |

用户首先应能看清当前目标、所选成员的实际状态、正在做的事与成果入口。完整介绍、目录和调度细节作为按需信息，不应挤掉这些事实。

## 0.5.1：看清战队，采用独立评审的反馈

版本功能：

- **事实投影：** 尽量让成员与工作事实不被大段介绍挤掉；不完整的结果仍明确保留限制。
- **所选成员概览：** 将用户选择的成员及其服务观察放在容易找到的位置，不借 DSH 作者的成功给核心成员标记成功。
- **成员分页：** 让剩余成员记录可以继续读取，不把当前页当作完整目录；不据此宣称所有任务列表都能完整续读。

**已经发生的协作：** DSH 委托核心 Codex 独立审查源码。Codex 执行了 **54 次原生工具调用**，复跑两个既有测试文件，**154 项通过**，仍指出三项 P2：

1. 配置服务卸载／替换后，晚到的成员回执可能重新进入当前视图。
2. 同一会话切换核心连接后，旧提交身份与晚回执可能被当作新连接的当前提交。
3. 超过 100 条的恢复任务列表被截断后，缺少提示与续读入口。

DSH 随后对三项**逐项独立复现并采纳**，明确第 1、3 项来自核心新增发现。154 项既有测试通过并没有覆盖这些缺口；这段证据支持限定的双 Harness 评审与反馈采用，不支持“所有成员已互通”或“普遍超过单家”。

**人工介入与恢复边界：** 首次核心任务以 `rc127` 结束：个人 Codex 启动脚本按 `HOME` 拼路径，隔离后目标不存在，模型并未启动。维护者保留隔离，仅让该验收服务的 `PATH` 优先使用已安装的原生 Codex，隔离环境下 `--version` 退出 0。旧任务返回 `no recoverable tasks`，未恢复旧 checkpoint；随后按已授权的 `previous_task_ref` 接续，旧失败保留。**这不是无人自治，也不是模型自行修好了环境。**

**交付边界：** 核心本轮只交审查文字，没有正式文件 export。DSH 保存了可见抄录，但未能匹配原 `final_ref` 的 hash，不能称为正式导出或 hash 核验通过。

**修复状态：** DSH 已在原生会话的隔离副本修复三项问题，完成失败反例、针对性测试及全量回归；操作者按基准 hash 核对四个输出后合回，再独立复跑通过。最终原生装包、画面和公开发行另按下方证据记录，不由绿测推断。版本证据与发行状态见 [0.5.1 记录](PLAN.md#v051)，安装目标见 [0.5.1 安装说明](MARKET.md#v051)。旧 tag、原包与历史回执不改写。

## 三种展示面，各自说明什么

先分清两个网站：[军团网页入口](https://vortexsean.com/)是登录工作区，提供账号实际开放的工作能力；[互动学习作品集](https://play.vortexsean.com/)展示六个独立教育试玩作品，**不是军团服务本身，也不是当前 DSH 版本的一次联合验收**。

作品集的[制作过程](https://play.vortexsean.com/#making)已经写明“一句话是起点”，军团在内部理解需求、设计实现、验证返工，并回到同一个作品继续改；也保留了 Codex 与人工持续迭代的说明。这里已经有产品理念，不能说原网站完全没有理念。下一步需要补上的是不同成员贡献、工具互用和后续任务采用改进的可见证据。

| 展示面 | 用户在这里得到什么 | 已经表达的理念／事实 | 还需要用运行事实显示什么 |
|---|---|---|---|
| **网站作品集** | 打开具体试玩作品，了解制作方式与当前边界。 | 已表达从想法出发、内部持续制作和返工、回到原作品改进；不同案例保留各自作者与人工参与。 | 哪些成员分别做了哪部分，谁实际用了谁的能力，哪项改进又被后来任务采用。六个作品不是协作次数，也不是能力排名。 |
| **DSH 入口** | 在自己的工作会话组队、发起工作、看成员状态与成果，继续或暂停。 | 0.5.0 有单作者交付；0.5.1 已有限定双 Harness 评审与反馈采用。作者、核心成员和计划分别呈现。 | 把已核实的贡献与成果放到主体验里；本轮反馈采用不能外推为全团工具互用或改进自动传播。 |
| **GitHub** | 理解这是什么产品，按固定版本安装，核对实现、条件与证据。 | README 保留“同一目标、互用工具、改进传播”的方向，并说明技术预览与版本范围。 | 用对应版本的真图、可核对的工作记录和产物说明协同价值；把愿景与已验证事实分开，不用代码、工具或测试数量冒充群体能力。 |

三者可以相互链接，但不能把各自的材料拼成一条没有发生过的因果链。已有理念不必从零重写；要把它接到用户看得见的工作事实上：

- **成员贡献：** 谁完成哪段工作，后来由谁接续或修改。
- **工具互用：** 谁通过哪个既有入口实际使用了哪项能力，结果回到了哪个任务。
- **改进采用：** 哪个后续真实任务用上了哪项改进，原作品或交付因此发生了什么可复验的变化。

这些是事实展示要求，不是增加固定执行流程或质量裁判。版本与范围分别见 [0.5.0 单作者记录](PLAN.md#v050)和 [0.5.1 协作与验收记录](PLAN.md#v051)。

本轮 0.5.1 的入口总览图须使用对应包的**真实 DSH 画面**，保留实际状态，不用概念图替代。真实对比录屏将在核对素材、版本和归因后补充；这里不放预设视频链接。剪辑与倍速需标明，不把展示时长当成任务完成耗时。

## 开始使用与运行边界

1. [按 0.5.1 说明安装连接器并明确启用](MARKET.md#v051)，使用自己的 DSH 模型与账号。
2. 在侧栏军团选择工作会话并组队；[原生自动流程](TEAM.md)会解释首次、周期、暂停、恢复和未确认结果。
3. 需要调用核心成员时，[独立安装并连接公开核心](CORE.md#public-core-install)，再配置对应成员的本人模型与权限。

没有核心时，当前 DSH 工具、Skill 与公开 GitHub 的发现、读源及可用的原生能力仍可使用。执行协作需要实际可用的核心、成员与授权，安装包不提供共享凭据，也不自动安装所有成员、模型或设备。

连接器与核心分包是分发边界，不是缩小战队目标。第一方许可与第三方许可、安装与构建权限、私有实例和正式成果出口的细节继续保留在 [README](../README.zh-CN.md#限制数据与许可)、[CORE](CORE.md)、[ECOSYSTEM](ECOSYSTEM.md) 与 [SECURITY](SECURITY.md) 中。
